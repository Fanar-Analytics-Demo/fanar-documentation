# Fanar Documentation

Source for the Fanar documentation site.

**Published site:** https://docs.fanar.tech

## Local development

Requires Node.js 20+ (see `.nvmrc`).

```bash
nvm use && npm install && npm start
```

Open http://localhost:3000/

Before pushing, run a production build — it catches broken links and bad image
paths that the dev server tolerates:

```bash
npm run build
```

Pushing to `main` builds and publishes to GitHub Pages automatically.

## Structure

Docs are organised by what the reader is trying to do, not by which upstream
project a page came from:

| Directory | Contents |
|---|---|
| `docs/start/` | First steps and core concepts |
| `docs/ask/` | Chat, Copilots, teaching Fanar your business, semantic layer |
| `docs/build/` | Queries, visualizations, dashboards, alerts, version history |
| `docs/connect/` | Data sources and Fanar Bridge |
| `docs/administer/` | Users, permissions, auth, multi-org, self-hosted setup |
| `docs/develop/` | REST API, local dev, query runners, agent architecture |
| `docs/reference/` | Environment variables, FAQ, troubleshooting, attribution |

Sidebar sections are declared in `sidebars.ts`; pages within a section are
autogenerated from the directory and ordered by `sidebar_position` frontmatter.

URLs from the previous structure are preserved via
`@docusaurus/plugin-client-redirects` in `docusaurus.config.ts`. If you move a
page, add a redirect.

## Writing docs

- **No bulk imports.** Parts of this site began as the Redash knowledge base and
  were adapted; `scripts/archive/import-redash-kb.mjs` must never be re-run. See
  the README next to it for why.
- **Verify against the app before documenting it.** Several pages have shipped
  claiming environment variables and integrations that don't exist in the
  codebase. If you document a setting, grep for it first.
- **Screenshots must show Fanar.** Many images under `static/img/docs/` are still
  inherited screenshots of a different product. Replacing them is tracked in
  [DOCS-PLAN.md](./DOCS-PLAN.md).

The long-term documentation plan is in
[DOCS-PLAN.md](./DOCS-PLAN.md); the page-by-page asset worklist is in
[DOCS-PHASE-2-WORKLIST.md](./DOCS-PHASE-2-WORKLIST.md).
